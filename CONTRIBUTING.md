# Contributing

Thanks for helping. This project handles evidence that people may rely on in legal contexts, so correctness and traceability matter more than speed.

1. Fork and create a branch.
2. `pip install -e ".[dev]"` and run `pytest` before and after your change.
3. Add a test for every bug fix or new behavior.
4. Keep the core rule intact: nothing generated by a model may be stored as verified evidence. Verified entries need a source, a location in the source, and a human reviewer.
5. Open a pull request describing what changed and why.

Do not commit confidential documents, client material, or anything under `data/`.
